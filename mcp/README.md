# Email MCP

This folder contains a local [Model Context Protocol](https://modelcontextprotocol.io/) server used by an MCP-capable agent or client to send job application emails through SMTP.

The server exposes one tool, `send_email`. The project command `/send-job-emails` uses that tool to send application emails for jobs in `output/filtered-jobs.json` and only marks a job as sent after the MCP call succeeds.

## What It Does

- Sends plain-text email through SMTP.
- Supports one or more recipients.
- Supports file attachments by local path.
- Supports scheduled sends by writing jobs to a local JSON queue.
- Provides a worker process that polls the queue and sends due scheduled emails.

It does not generate email content by itself. Email content is generated by the project command flow from:

- `profile/job-profile.md` for candidate facts.
- `profile/email-body-rules.md` for tone, structure, and wording rules.
- `output/filtered-jobs.json` for the target job messages.

## How To Start It

The included project configuration starts the server with this command:

```bash
npm --prefix mcp start
```

If your agent or MCP client supports local MCP servers, configure it to run that command from the repository root:

```json
{
  "mcp": {
    "email": {
      "type": "local",
      "command": ["npm", "--prefix", "mcp", "start"],
      "enabled": true
    }
  }
}
```

Most MCP clients load server configuration at startup. After changing MCP configuration or SMTP environment variables, quit and restart your agent or MCP client.

## Environment Variables

Set these variables in the shell that starts your agent, MCP client, or the MCP process:

| Variable | Required | Purpose |
| --- | --- | --- |
| `SMTP_HOST` | Yes | SMTP host, for example `smtp.gmail.com`. |
| `SMTP_PORT` | Yes | SMTP port. Use `587` for STARTTLS or `465` for secure SMTP. |
| `SMTP_USER` | Yes | SMTP username, usually your email address. |
| `SMTP_PASS` | Yes | SMTP password or app password. For Gmail, use a Google app password. |
| `SMTP_FROM` | Yes | Sender address shown in outgoing email. Usually the same as `SMTP_USER`. |
| `EMAIL_QUEUE_FILE` | No | JSON queue file for scheduled emails. Defaults to `mcp/scheduled-emails.json`. |

Example:

```bash
export SMTP_HOST=smtp.gmail.com
export SMTP_PORT=587
export SMTP_USER=your-email@gmail.com
export SMTP_PASS=your-google-app-password
export SMTP_FROM=your-email@gmail.com
```

`mcp/.env.example` is a reference file. The server reads environment variables from the process environment; it does not load `.env` automatically.

## Commands

Install dependencies:

```bash
npm install --prefix mcp
```

Check JavaScript syntax:

```bash
npm --prefix mcp run check
```

Run tests:

```bash
npm --prefix mcp test
```

Start the MCP server directly:

```bash
npm --prefix mcp start
```

Run the scheduled email worker:

```bash
npm --prefix mcp run worker
```

In normal agent usage, you do not need to start the MCP manually if your MCP client is configured to start it. For manual testing, use `npm --prefix mcp start`.

## `send_email` Tool

The tool accepts this input:

```json
{
  "to": "recipient@example.com",
  "subject": "Application for Backend Developer role",
  "body": "Hello, ...",
  "attachments": ["/absolute/or/relative/path/to/cv.pdf"]
}
```

`to` can also be an array of recipient addresses:

```json
{
  "to": ["first@example.com", "second@example.com"],
  "subject": "Application",
  "body": "Hello"
}
```

On immediate sends, the server returns a JSON response containing:

- `ok: true`
- `messageId`
- `accepted`
- `rejected`

If SMTP configuration is missing or sending fails, the MCP response is marked as an error and the job should not be marked as sent.

## Attachments

Attachments are passed to Nodemailer as local file paths. The application email command should only attach files that exist and are appropriate for the target job, such as a CV or portfolio PDF.

Keep personal attachments private. Resume and CV files can live in `profile/documents/` or another private folder, and they can be versioned in your own private fork if that is useful to your workflow.

## Scheduled Emails

Add a `schedule` value to queue an email instead of sending it immediately:

```json
{
  "to": "recipient@example.com",
  "subject": "Application follow-up",
  "body": "Hello, ...",
  "schedule": "2026-08-10T13:00:00.000Z"
}
```

The schedule can also use an object with `sendAt`:

```json
{
  "to": "recipient@example.com",
  "subject": "Application follow-up",
  "body": "Hello, ...",
  "schedule": {
    "sendAt": "2026-08-10T13:00:00.000Z"
  }
}
```

Scheduled emails are written to `EMAIL_QUEUE_FILE`, or to `mcp/scheduled-emails.json` when `EMAIL_QUEUE_FILE` is not set. The queue file is ignored by Git.

Run the worker to process scheduled jobs:

```bash
npm --prefix mcp run worker
```

The worker polls every 10 minutes. Due or overdue jobs are sent and removed from the queue after a successful send. Failed jobs remain in the queue with attempt metadata so a later poll can retry them.

## Troubleshooting

- `Missing required SMTP environment variables`: set all required `SMTP_*` variables in the shell that starts your agent, MCP client, or MCP process, then restart it.
- Gmail authentication fails: use a Google app password, not your normal Google account password.
- Scheduled emails do not send: confirm the worker is running and that `EMAIL_QUEUE_FILE` points to the same queue file used by the MCP server.
- Attachments fail: verify each attachment path exists from the repository or process working directory where the MCP runs.
- Config changes do not apply: restart your agent or MCP client because MCP configuration is usually loaded at startup.
